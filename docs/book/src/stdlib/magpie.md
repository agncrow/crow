# magpie

The log as a directory of batch files: each commit one file written once, holding its rows' positions, sorted by key, with the statistics a reader prunes by; appends, reads from a position, the latest version of each key, lookups, and a sequencer that refuses a stale read.


Import with `use magpie`. The log as a directory of batch files, written in Crow on the sys layer (design rule 20): each commit is one file, written once by the kernel (sys, `batch_write`) — a frame given a position per row in a column `_pos`, its rows sorted by the key columns, and in the file's head the statistics a reader prunes by (min, max and a bloom filter per column, a filter over the words of each text column indexed). One file is at once the log entry (positions), the level-0 segment (sorted, with statistics) and the search index (word filters, and the counts a search's scoring reads). The numbering, the sequencer, the reads, the search and the catalog's state are the module's; a log is a directory path, a snapshot a position.

```
use magpie
use frame

made = mkdir['orders']
first = batch['orders', frame.new[id = [1, 2], qty = [10, 20]], by = ['id']]
log[first]                                   --- 0
second = batch['orders', frame.new[id = [2, 3], qty = [25, 30]], by = ['id']]
log[head['orders']]                          --- 3
log[latest['orders', ['id']].qty]            --- [10, 25, 30]
log[lookup['orders', ['id'], ['2']]._pos]   --- [1, 2]
stale = commit['orders', frame.new[id = [2], qty = [26]], by = ['id'], seen = 1, columns = ['id'], equal = ['2']]
log[stale.reason]                            --- conflict: id = 2 was written at position 2, after snapshot 1
log[merge['orders', by = ['id']]]            --- orders/000000000000-000000000001.segment
log[latest['orders', ['id']].qty]            --- [10, 25, 30]
```

**Nodes and shards.** A second node is a follower of the log (`share`, `follow`): it holds the same files, reads them with the same verbs, and serves what the leader serves; the leader is the one process that writes, and a follower promoted by the operator writes from the head it holds — there is no election, since every file a follower lacks is one `follow` fetches, and a leader that writes nothing more is followed to its last file. A table too large for one node is split into logs by a key (`orders_a`, `orders_b`, a directory each, on a node each), and a query runs the same verbs on each and stacks the answers: `frame.stack[latest['orders_a', k], latest['orders_b', k]]`, or a reduction over each log's part. Nothing in the module knows a shard: the placement is the program's, written where the logs are named.

**Design Note: one file per commit, and the module over it.** Considered: a write-ahead log of row-shaped entries, a memtable flushed to sorted segments and postings built beside them — three writes per row, three structures (rejected: every durable database pays them, and no reader of this log needs them apart: a batch file sorted by key with statistics in its head is the segment a scan prunes, the index a search prefilters, and the entry a consumer reads by position, so the row is written once at commit and again only when files are merged). Considered, for the kernel's reach: the sequencer in the runtime under a lock (rejected: the validation is policy, which is Crow's; the kernel claims a number atomically — a file linked into place only where none exists — and the Crow module validates every file before the number it claims, so a slip is a retry, not a hole). Considered, for the name: `log` (taken by the console), `store` (sys's `store` row), `journal` (rejected: long), `lake` (the first name, rejected 2026-10-26: the industry's word for raw files other engines query, where this store holds its state and runs its own engines), `keep` (a web option), `hold` (the spec's verb on every page), `ledger` (the log alone, not the engines over it), `corvid` (heard as covid) — `magpie`, the corvid that gathers everything into one nest, a bird as crow and finch are. The position column is `_pos`, a name no table of a program is likely to use; a frame that holds one is refused. A value looked up is written as text so that one function serves every column kind, compared with `str` of the column on both sides and read by the kernel as the column's kind for its filter.
