## Not possible in Crow as it is (6)

- [Clipboard manager/display](https://rosettacode.org/wiki/Clipboard_manager/display): a desktop GUI window (with an always-on-top pin) watching the system clipboard as copies are made: Crow has no GUI toolkit (its views are pages served to a browser, which can neither watch the system clipboard nor stay on top) and reaches the clipboard only through the shell (pbpaste, xclip); a served program also never ends, so the runner could not hold it to an output. The queue of ten with its clear is trivial without them, so no .co
- [Hello world/Line printer](https://rosettacode.org/wiki/Hello_world/Line_printer): no line printer is attached: the Unix entries write to the device /dev/lp0 (or /dev/lpt0, /dev/ulpt0, or pipe to the lp/lpr spooler), which is outside the current directory and absent on this machine, so nothing is written; in Crow the whole program would be one line, written = write['/dev/lp0', 'Hello World!\n'] (or shell['echo Hello World! | lp'] for the spooler), neither run here
- [Machine code](https://rosettacode.org/wiki/Machine_code): Crow has no raw memory, pointers or addresses (the runtime makes every value), no way to mark memory executable and no foreign call, so the opcodes cannot be poked into memory and run; shell[] reaches outside, but a C program it compiled would be doing the poking, not Crow; an x86 emulator would answer 19 without running machine code
- [Mutex](https://rosettacode.org/wiki/Mutex): a Crow program shares no mutable state between threads: a parallel loop's rounds share nothing, and process memory (use memory), whose revise held a name's lock, is the standard library's own since 2026-10-28 (Vijay's decision) -- there is no mutex for a program to create, lock or unlock. The program over revise is withdrawn; probing it had found findings/mutex-1.co (two names revised in opposite orders deadlock the compiled program) and findings/mutex-2.co (a function that only fails, handed to revise, does not build compiled), both now inside the standard library only
- [Video display modes](https://rosettacode.org/wiki/Video_display_modes): Crow has no control of the display's (or the terminal's) video mode: nothing in the spec sets a resolution or a text mode. The modern entries (Go, Kotlin, Wren, Julia, UNIX Shell) run X11's xrandr; Crow could hand the same command to shell['xrandr -s 1024x768'], but that is xrandr's control, not the language's, and it cannot be run here (macOS has no xrandr, and a run must not switch the user's display), so no program is written
- [Write to Windows event log](https://rosettacode.org/wiki/Write_to_Windows_event_log): Crow runs on macOS and Linux (on Windows only inside WSL, as the book's Getting Started says) and has no Windows event log API: no ReportEvent/EventCreate binding and no FFI to reach advapi32. The one route would be shell['eventcreate.exe /T INFORMATION /ID 123 /L APPLICATION /SO Crow /D ...'] through WSL's interop (as the Go and Julia entries run EventCreate), which cannot be run or checked on this machine; the nearest native equivalent, syslog through logger, is not the task's log (and would write into this machine's system log at every run), so no .co

## Done in part (23)

- [Accumulator factory](https://rosettacode.org/wiki/Accumulator_factory) — [`accumulator_factory.co`](accumulator_factory.co): prints 8.3, but Crow has no closures or captured mutable state by design (spec: No Lambdas or Closures, No Ambient Mutability): the accumulator is a record threaded through accumulate[g, i], not a returned function (rule 4); int vs float is decided statically, so with any float accumulator every total is a float (rule 2, by the spec rule that a parameter ever handed a float is a float)
- [Arena storage pool](https://rosettacode.org/wiki/Arena_storage_pool) — [`arena_storage_pool.co`](arena_storage_pool.co): Crow has no allocators, pointers or storage pools a program chooses (the runtime makes every value and lets it go after its last read), so the header explains that, and the arena is modelled as a value: ints placed one at a time in slots known by handles, freed as a group by moving the top back to a mark, the slots used again
- [Closures/Value capture](https://rosettacode.org/wiki/Closures/Value_capture) — [`closures_value_capture.co`](closures_value_capture.co): Crow has no closures or anonymous functions by design (spec: No Lambdas or Closures), so the ten are records each holding its own copy of the loop counter i, run by one named function (closure conversion by hand); functions 0..8 answer their squares while i has moved on to 10. Holding the function itself in the record beside i is refused when called through the field (findings/closures_value_capture-1.co)
- [Compile-time calculation](https://rosettacode.org/wiki/Compile-time_calculation) — [`compile_time_calculation.co`](compile_time_calculation.co): Crow has no compile-time evaluation of its own (no macros, constant functions or comptime; Appendix B: "nothing to compute at compile time"), so 10! is written as a product of literals, which the Rust compiler under Crow folds in the binary crow build makes (checked: the release binary loads 3628800 as an immediate, mov #0x5f00 / movk #0x37); the dev build of crow run multiplies at run time and the interpreter has no compile time; a factorial function with a loop is a big int and never folds. The header discusses the limits
- [Extend your language](https://rosettacode.org/wiki/Extend_your_language) — [`extend_your_language.co`](extend_your_language.co): no macros or user-defined keywords/blocks (fixed syntax by design), so no new control structure; shown instead: if2 as a function taking the two conditions and the four branches as named functions (only the chosen one runs), used for FizzBuzz, nested, and guarding a division; a branch sees none of its caller's locals (no closures) and one if2 serves one kind of argument (a function taking a function is not copied per kind)
- [Fixed length records](https://rosettacode.org/wiki/Fixed_length_records) — [`fixed_length_records.co`](fixed_length_records.co): sample.txt written, blocked to infile.dat (dd conv=block), each 80-column record reversed into outfile.dat, both shown unblocked (outfile matches the Go output; files checked byte for byte against Python), NUL/line end/tab inside a record round-trip; bonus: text to a 1024-byte Forth block (16 x 64, long line cut, last block padded) and back without trailing spaces; files removed at the end. Missing: 8-bit completeness - a program reads and writes files only as UTF-8 text (read refuses bytes 128-255: "it is not text (UTF-8)"; use sys, which has bytes/file/store, is refused to programs)
- [Function prototype](https://rosettacode.org/wiki/Function_prototype) — [`function_prototype.co`](function_prototype.co): Crow has no prototypes (the task says such languages are omitted): a function or record is declared only by its definition and found wherever in the file it is written, its kinds inferred from use; the program shows what stands in for each part (calls before definitions, mutual recursion, no-argument, two-argument, defaults, named arguments, a subroutine, a function as a value) and says argument counts and names are checked against the definition before running; varargs have no form (a list is passed instead)
- [Generator/Exponential](https://rosettacode.org/wiki/Generator/Exponential) — [`generator_exponential.co`](generator_exponential.co): no generators, coroutines or closures in Crow: each generator is its state in a record (Powers, Without) and a step function answers it moved on, the caller threading the state; the filter takes powers generators only (a step function held in a record field is the open function-in-a-field finding). Output matches (529 ... 1089). Top-level collecting first refused: findings/generator_exponential-1.co (an empty list pushed a function's answer, then joined), worked around with take/drop functions
- [Inner classes](https://rosettacode.org/wiki/Inner_classes) — [`inner_classes.co`](inner_classes.co): Crow is not object oriented: no classes, no methods (a struct is pure data), and a struct may be declared only at the top level, so there is no inner class; the stand-in shown (as the task allows for such languages) is a record OuterInner keeping the Outer record it was made from in a field, constructor functions, and a method-like function reading both records (the Java entry's 22 + 20 = 42); missing: nesting, encapsulation, and a live link to the outer (values never change in place, so the inner holds the outer as it was); findings/inner_classes-1.co (a struct inside a body is refused with no line and in a lowering phase's words)
- [Inverted syntax](https://rosettacode.org/wiki/Inverted_syntax) — [`inverted_syntax.co`](inverted_syntax.co): Crow has no inverted form: a statement modifier (`x = true if c`, refused: a line holds one statement) and an inverted assignment (`6 = a`, refused: invalid assignment target) are not in the language (one way to write a conditional, spec: No Ternary Expression); shown: the traditional if, a guard written first, and the nearest inversion, as the Go/Kotlin entries do: a function taking the value or a named action first and the condition after, written in that order by then (`true then iif[raining]`, `take_umbrella then only_if[raining]`)
- [Jump anywhere](https://rosettacode.org/wiki/Jump_anywhere) — [`jump_anywhere.co`](jump_anywhere.co): Crow has no goto, labels or continuations (its control flow is structured by design), so no jump lands anywhere: shown are break and continue in a while, return out of two nested for loops, a failure made three calls down that makes each caller return at its first decision on it until the top asks .ok (the non-local exit exceptions give), a goto program (the Python entry's restarted loop) run as a while loop over labels held in a variable, and exit[0] leaving the program from inside a loop
- [Keyboard input/Obtain a Y or N response](https://rosettacode.org/wiki/Keyboard_input/Obtain_a_Y_or_N_response) — [`keyboard_input_obtain_a_y_or_n_response.co`](keyboard_input_obtain_a_y_or_n_response.co): the answer is read as a line from standard input (keyboard_input_obtain_a_y_or_n_response.in): lines are read until one is Y or N (either case, trimmed), others ask again, end of input is no answer. Missing (the task's point): a single key press without Enter and flushing keys pressed before the question - Crow has no terminal control (raw/non-canonical mode, input flush)
- [Memory layout of a data structure](https://rosettacode.org/wiki/Memory_layout_of_a_data_structure) — [`memory_layout_of_a_data_structure.co`](memory_layout_of_a_data_structure.co): Crow has no control over memory layout: no fixed-width or packed record fields, no bit fields, no field order in memory; shown instead: the 9-pin plug as a record of named pins and as one int's bits (pin n at bit n-1) set, cleared and tested by name with use bits, converted both ways (RI|TD|CD = 0x0105, as Go's entry)
- [Metaprogramming](https://rosettacode.org/wiki/Metaprogramming) — [`metaprogramming.co`](metaprogramming.co): Crow has none of what the task counts (no macros, preprocessor, user-defined operators or syntax, or eval: macros rejected by design, spec "Names Are Never Ambiguous" rule 5); the program shows the nearest things it has: the parser's rewrites (a then chain inline and as lines, x in xs), a function compiled once per kind it is called with, a group of functions dispatched by the compiler, and type[] at run time; describe/apply (function reflection) are the standard library's own and a program's call of them is findings/metaprogramming-1.co; largest is shown on ints and text only, working around findings/metaprogramming-2.co (ints, floats and a third kind: internal error)
- [Metronome](https://rosettacode.org/wiki/Metronome) — [`metronome.co`](metronome.co): no sound: Crow has no audio output and writes text files only (no sound file for a player either), and no screen area to blink (no cursor control), so each beat is a printed line with its time, bar and beat and a block indicator (full block TICK high, light block tock low); tempo and an H/L bar pattern are parameters (4/4 at 120, 3/4 at 90, 5/4 at 172); beat times counted from the start so they cannot drift; the saved run prints at once (same every run), and `crow run metronome.co live` waits for each beat with sleep (checked in both modes: lines arrive on time)
- [Musical scale](https://rosettacode.org/wiki/Musical_scale) — [`musical_scale.co`](musical_scale.co): no sound: Crow has no sound device, and a program cannot write the bytes of a MIDI or WAV file (bytes are the standard library's own layer, use sys, refused in a program; write takes text); shown instead: the eight notes from middle C with MIDI numbers and 12-TET frequencies at A4 = 440 Hz (261.626 ... 523.251), and the scale as a text score in ABC notation (the task's score-sheet alternative)
- [Nautical bell](https://rosettacode.org/wiki/Nautical_bell) — [`nautical_bell.co`](nautical_bell.co): the bells of one fixed day (2026-10-28, GMT) as written notices (the task allows "Two bells gone") with the strokes in pairs, watch by watch, the dog watches sharing one count of eight; not done: ringing by the wall clock as the hours pass and the sound (the run reads no clock, so every run prints the same)
- [Nested function](https://rosettacode.org/wiki/Nested_function) — [`nested_function.co`](nested_function.co): the text is printed, but Crow has no nested functions or closures by design (spec: No Lambdas or Closures; a function sees only its parameters): make_item is a top-level function handed the separator and the counter, answering the item and the next count as a record, which make_list keeps; a function declared inside a body is refused with a position-less internal-looking message (findings/nested_function-1.co)
- [Pragmatic directives](https://rosettacode.org/wiki/Pragmatic_directives) — [`pragmatic_directives.co`](pragmatic_directives.co): Crow has no pragmas proper (nothing a program writes turns a check off or changes how its text is read); the header lists what steers a run: use (a module's names, in the file that writes it; as m for an alias), cpu[n] (every parallel loop after it, in the code after it and the functions it calls; in a function until it returns), gpu[] / gpu[n] (tensor work on the GPU from then on, linked only where written), the crowfile's cpu, gpu and schema keys, and CROW_SCHEMA for one run; the program shows cpu[1] in a function, the count restored on return and cpu[2] at the top level, with use math as m, the answers unchanged as they must be (a parallel loop only computes); the effect is on time alone, measured apart (a million lengths compiled: 0.4-0.8 s on every core, 3.4 s under cpu[1], 1.7 s under cpu[2]); gpu[] and the crowfile are described, not run (no GPU work here; a crowfile would change every run in its directory)
- [Random number generator (device)](https://rosettacode.org/wiki/Random_number_generator_(device)) — [`random_number_generator_device.co`](random_number_generator_device.co): the device is read only when the program is given the argument device: shell runs od on /dev/urandom for four bytes, joined into a 32-bit number (checked in both modes, a new number each run); a program has no byte read of its own (read takes text; sys random/file are the standard library only), hence the shell; by default, and so in the .out, four bytes from the seeded generator are joined the same way
- [Rate counter](https://rosettacode.org/wiki/Rate_counter) — [`rate_counter.co`](rate_counter.co): timing is the point and the saved output must not change, so the times and rates print only with the argument time (checked in both modes: the meters take the job as a function; 5 timed rounds of 100,000 Collatz-length jobs, and jobs for 2 s with the count read at each half second); without it the same fixed work prints its counts (10,753,840 steps a round, checked in Python). The clock documented: now[] is the wall clock (not monotonic) held to the millisecond, so each measured span is a tenth of a second or more
- [Sine wave](https://rosettacode.org/wiki/Sine_wave) — [`sine_wave.co`](sine_wave.co): Crow has no sound output: the program writes 5 s of 440 Hz as sine_wave.wav (PCM, 8 bits, 32 kHz; checked with afinfo and Python's wave: 5.000000 s, peak at 440 Hz; both modes write the same bytes), reads it back to show its header and two periods in characters, and only given play hands it to the system's player through shell (afplay or aplay; tested at volume 0). A program writes text, so every byte is kept below 128 (bytes 128-255 would be two bytes of UTF-8; use sys is refused to programs): samples swing about 64 faded in from 127, and 32 kHz x 5 s keeps every header byte below 128; removed unless keep
- [Stream merge](https://rosettacode.org/wiki/Stream_merge) — [`stream_merge.co`](stream_merge.co): Crow has no file handle a program reads a line at a time (read and io's lines take a file whole; sys's file[path, from, n] is the library's own), so the sources read through shell (tail -c +offset | head -n K, byte offsets counted from base64 lengths; shell trims trailing whitespace from stdout, kept with an echoed dot) and the sink appends through shell printf: merge of 2 (one buffered line each) and of N (binary heap of records), order as a function; the Go entry's streams (2 3 14 15 17 18; 2 2 3 3 5 7 14 15 17 18) and unixdict dealt at random into 7 files merged back byte for byte. Worked around findings/stream_merge-1.co (a function value called with a fallible argument in one place and plain ones in another does not build compiled) by making the reader infallible
