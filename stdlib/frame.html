The Crow Language Specification

frame

Column-oriented data frames: load, select, masks, sort, group, join, and time handling.

Import with use frame. Column-oriented DataFrames for tabular data. See docs/frame-module.md for design details.

Column references: strings for names, expressions for computation. Naming a column is a string; computing on a column is a normal Crow expression over df.col. Every line is plain Crow — there is no special evaluation inside frame calls.

A datetime column holds moments (see Moments): a column written from a list of moments, or one repeated, is one, fill fills one with a moment, a cell read one at a time is a moment, a mask compares the column with a moment, and load reads one from ISO 8601 text and save writes it back as such.

A vector column holds vectors of one width — an embedding per row. It is written from a matrix (frame.new[e = [[1.0, 0.0], [0.0, 1.0]]], df.e = stack[rows]: a tensor of two axes, a row each) or from a list of vectors (tensors of one axis, or lists of numbers), every one of the width the first has: another width, an empty vector or a tensor of three axes stops the write, naming the row (column 'e': a column of vectors holds vectors of one width, and row 1 has 1 numbers where the first has 2); a tensor of one axis written as a column stays a column of its numbers, and no one vector is repeated down the rows. A cell read one at a time (df.e[i], a loop over df.e) is a tensor — a missing one an error of reason missing whose placeholder is zeros of the width — tensor[df.e] is the matrix of the rows, len[df.e] the row count, str[df.e] a column of text, and a frame shows the cell as a tensor shows ([1, 0]); .dtypes names it vector. Two columns of vectors compare whole (df.e eq g.e), an operator over the column works on its matrix (df.e * 2.0, as df.a * 2.0 works on a number column's vector), and a mask compares a vector with nothing (df.e eq v is refused). The column passes through select, a mask, head, tail, stack (one width; a column of no rows takes the other's), join (as a key too, equal vectors matching), group with count, first and last (and as a key), where (both sides vectors of one width), window with lag, lead, first, last, count and distinct, unique, pivot (as the values), complete, sample and rename; it has no order and no arithmetic cell by cell, so sort by it, a sum, mean, min, max, median, deviation or percentile over it (in group or window), rank, fill, unpivot of it, a text function over it and bucket stop the program, naming the column (sort: column 'e' holds vectors, which have no order); int[…] and float[…] of it are every cell missing, moment[…] of it is refused, and join of it is refused as join of a matrix is (a vector shows as no text: join[str[df.e], sep] joins the cells' text). save writes it as JSON records (a list of numbers per cell, null where missing) or as Parquet (a fixed-size list of float64, which Arrow readers hold), and load reads either back as vectors — a JSON column every present cell of which is a list of numbers of one width is one; CSV cannot hold one, so save as CSV is refused (save: column 'e' holds vectors, which CSV cannot hold — save as .json or .parquet). A loaded frame's cell handed where a tensor is taken (norm[df.e[i]], dot[v, df.e[i]]) says the column holds vectors, and the load is held to it as to any kind. Magpie holds the column (see magpie): a float chunk of rows × width, narrow keeping 32 bits, never a key and never the time column, and nearest[dir, column, vector, k] finds the rows by it. The same in both modes (parity 303).

Design Note: a column of vectors. Considered: one float column per dimension (what a frame could hold until 2026-10-27 — workable through Magpie's column projection, and no one would call it good: an embedding of 768 dimensions is 768 columns and a cell read 768 reads); a column of parsed values holding lists (every cell read first, no kernel over the column); a tensor kept beside the frame with a row per frame row (two values kept the same length by hand, and lost by every verb). Decided (Vijay, 2026-10-27; Magpie's magpie-design.md, "Before phase 10"): a fixed-width vector per cell — Column::Vectors(width, Vec<f64>) in the runtime, the rows laid flat, so a cell is a slice, the column its matrix and Magpie's chunk a float chunk of rows × width — and no new type in the compiler: the cell's type is a tensor of one axis (Ty::Column(Tensor(Float, [width]))), so inference, the loop item rule, the index rule and the emitter's cell read follow from the column's cells as every column's do. The index per segment (an HNSW of our own) is the step when a corpus asks for one; nearest is exact until then, and the vectors package's flat index says the same of itself.

Properties: .shape, .columns, .dtypes. Column access: df.age. len[df] returns the row count. Aggregation names for group and window: 'sum', 'mean', 'min', 'max', 'count', 'median', 'std', 'var', 'first', 'last', 'distinct' and a percentile 'p1' to 'p99' ('p90'). A median and a percentile are interpolated between the two cells they fall between (as pandas, numpy and Julia interpolate), a float; std and var the population's (as stats and std of a tensor answer), floats; first and last the first and the last present cell, in the column's kind; distinct the count of distinct present cells, an int. Join kinds: 'inner' (the default), 'left', 'right', 'outer', 'semi', 'anti', 'asof'.

A column is written the way it is read. df.qty reads a column, and df.qty = values writes it where the frame lies: a new column, or the column replaced; values a list, a tensor or a column as long as the rows, or one value repeated down them (df.side = 'buy'); ints held as a tensor ([1, 2]) make a column of ints. Values of another length stop the program (column 'b' is given 3 values, and the frame has 2 rows), as a write at a position that is not there does. The frame is whatever holds it — a variable, a record's field (book.prices.doubled = …), a list's item — and a function writes the frame it was handed, its caller's copy untouched. A column written through a record's field or a list's item is read as the program runs: the field's type is every record's and the item's every item's, so neither can carry the column, and the frame there is open from that line on (as a frame whose columns show only as it runs is). After a dot, a column's name reads as text does: a backtick inside it is an interpolation, so df.lag_k = … writes the column named by the text lag_ and k, and df.name = … the column a variable names; read the same three ways (df.lag_k, `df.`name). A name no dot can write — a header with a space, a keyword — is reached through the marks, df.'in px', and that is the escape, not the idiom. A computed name is a frame's alone: a record's fields are fixed before the program runs (`.`f of a record is refused), and a map's key is m[key]. Each named argument of frame.new[sym = …, qty = …] is such a write, so the literal and the dot are one mechanism.

Design Note: a column is written by the dot. Considered: with[df, 'name', values], a verb answering a new frame (shipped until 2026-10-20; rejected: a verb for what the dot already reads, the quoted name, the assignment back, and the chains it bred — with[with[frame.new[], 'symbol', syms], 'rsi_3m', vals]); set[df, name, values], the map's verb lifted to frames (rejected: the same shape as with); a method, df.batch['name', values] (rejected: a second call shape for one kind, and a method's name reserved on every frame's columns — pandas's df.count); df[name] = values, the index write (rejected: a frame's index is a mask, by the decision of 2026-10-16, and it would mean a column on the left of = and rows on the right); a then chain of column steps (rejected: a step that mentions the frame changes shape); and no computed name at all, rename after a write under a placeholder (rejected: a loop writing a column per k was two lines of indirection). Decision (Vijay, 2026-10-20): the dot writes, as it reads; after a dot a name reads as text does, a backtick inside it an interpolation; with is removed from the language (an unknown name, as every removed builtin is). The write is the hidden row __set_col and the computed read __col, found by the lowering through their rows' properties (Prop::ColumnWrite, Prop::ColumnRead), so the compiler names neither; a refusal names the form as the program writes it.

Text, casts and a moment's fields over a column. lower, upper, trim, replace and sub of a frame's column answer a column of text, each present cell as the text function answers it, a missing cell staying missing (a sub pattern that is none stops the program: a cell cannot carry the reason); part in c of a text column (whether each cell holds the part: 'AA' in df.sym), starts and ends answer a mask, a missing cell false. int, float, str and moment of a column convert every cell as the one-value form does — text read as a number or a moment, a number as seconds, a moment as its seconds, anything as the text it shows — a cell that cannot be converted missing, which the column's .ok says (int[df.price] cuts toward zero; str[df.day] is text that load would read back as ints). df.at.hour, .year, .month, .day, .minute, .second, .weekday and .offset of a column of moments are a column of ints, each read in its own zone. (len[df.col] stays the column's length: a cell's length is len[df.col[i]].)

A column the frame lacks, an aggregation or a join it does not know, a mask of another length than the rows, a negative count for head or tail, a fill value of another kind than the column's (an int fills a float column), and a count of arguments the function does not take stop the program with the reason (see When a Program Stops), in both modes, as df.col of a missing column does. A column written from another (df.b = df.a) keeps its missing cells.

Several keys, pivots and windows. group[df, ['symbol', 'day'], ['qty', 'sum']] has a row per symbol and day, symbol and day as they were and qty_sum an int, as qty is. pivot[df, 'symbol', 'day', 'qty'] lays the days out as columns, one row per symbol, with qty in the cells — the columns are the days' text ('1', '2'), so they show as the program runs and their cells are read as a loaded file's are, with int[…], float[…] or str[…]; a symbol and day two rows share stops the program (pivot: 'b' and '1' appear 2 times — one row per pair: aggregate first, group[frame, ['sym', 'day'], ['qty', 'mean']]). window[df, 'qty', 'sum', by = 'symbol'] is each row's running total within its symbol, window[df, 'px', 'lag', n = 1, by = 'symbol'] the symbol's previous price, missing on its first row, and window[df, 'px', 'rank'] each price's rank over the whole frame; the trailing forms (n = 3) take the rows there are at a partition's start. A window's cells are typed by what it computes — a sum, min or max in the column's kind, a float for mean, an int for count and rank, the column's own cells for lag and lead, which can be missing — and a column a window or a pivot names that the frame lacks is refused before the program runs, as a key is. A column handed to sum, mean, min or max holds numbers, and a missing cell stops the program as it does where numbers are taken. The same in both modes.

Design Note: pivot reshapes, group aggregates. Considered: pivot[df, rows, cols, values, how = 'sum'], a pivot table that aggregates the rows sharing a pair, as a spreadsheet's does and pandas's pivot_table. Decided (2026-10-02, with the frame work): one way to aggregate — group — and one way to reshape; a pair two rows share stops the program, naming the group that aggregates it. Rows and columns come in ascending order of their cells, where group keeps the order first seen: a pivot is read as a table, and its days and symbols are looked for by their order.

Design Note: percentiles are words, keys are lists, and the other names are the old ones. Considered, for a percentile, ['px', 'quantile', 0.9] — a list holds one kind, and 'quantile 0.9' as text — a name with a space in it. Decided: 'p90', one word for the 90th percentile, as a column is named by it (px_p90); 'median' is 'p50' by its own name. Considered, for a join on several keys with an as-of clock, pandas's and polars's by = beside on =. Decided: one list of keys, the last the clock — join[bars, signals, ['symbol', 'at'], 'asof'] reads as the match it is. Considered, for a conditional column, a new word (pick, choose); decided: where, math's word for the same operation over tensors — one name, the kinds picking the row. Considered, for the reverse of pivot, pandas's melt and polars's unpivot; decided: unpivot, naming its two new columns variable and value as both do, so a program ported from either keeps its names. Considered, for rows without a missing cell, dropna; decided: complete, the word the masks section already used for them. A bucket's edge is the local midnight of the moment's own offset (a day in New York starts at 04:00Z), where pandas floors a zone-aware moment in UTC: a bar is drawn on the exchange's clock, and a moment carries the offset it was written in for this. A fill by direction is fill[df, col, how = 'forward'], since fill[df, col, 'forward'] would be the text in a column of text. A text function over a column keeps its name, as the arithmetic operators keep theirs; len of a column stays its row count.

Design Note: the frame module is held to pandas. tests/parity/185_frames_held_to_pandas.co computes 59 cases over four tables (tests/frames/data/) and compares each with what pandas 3.0 answered (tests/frames/expected/, written once by tests/frames/reference.py): loading and its kinds, select, six filters, five sorts, head and tail, four groups, a pivot, running, trailing, shifted and ranked windows, the four joins, stack, three fills, unique, rename, a computed column, reductions, moments moved between offsets, and quoted cells read and written back — every column, kind and cell the same, in both modes (2026-10-06); and, since 2026-10-07, the other aggregates (a median, percentiles, the deviation, first and last, distinct), windows of them trailing and running and over a span of six hours, sorts on two and three keys, joins on two keys of every kind, distinct rows, an as-of join, six-hour buckets and the bars over them, text and a moment's fields over a column, an unpivot, fills by direction, complete rows, a conditional column and casts. What that round found: pandas's rolling kernels compile to fused multiply-adds, so a deviation or a percentile agreed to twelve digits and not the last — the runtime's mul_add now computes the same rounding, and a window whose squared sum collapsed is computed afresh as pandas's is. What it found and changed: a CSV column of true/false had loaded as text (so save then load lost the kind) and a quoted cell had been split at its comma; the sort was unstable and a missing int cell sorted as 0 — now stable, missing cells last either way, as pandas sorts them (polars puts them first, Postgres first or last by direction: one rule was needed, and the one that keeps the present cells together was taken); every aggregate of group was a float and a sum over text silently 0; a window's sum over ints was a float; unique answered text for every column, and gave up scanning after a long stretch without a new cell; a right or outer join's unmatched row had lost its key; a sum over floats differed from pandas and numpy in the last digit — a group or window total is now compensated as pandas keeps one (Kahan, with pandas's separate compensations for the cells added and taken off, and its exact answer for a window whose cells are all one value), and sum[t] adds as numpy does, pairwise; and, in the compiled program alone, a moment cell read one at a time was seconds where the interpreter read its text, a field of a moment that can fail (tz's answer) did not build, [1, 2] written as a column made a column of floats, a list a function started empty and pushed onto did not build, and a list of a loaded file's cells, read one at a time, did not join. And in crow test alone, window[…, by = …] and request[…, timeout = …] were refused in every test block: the runner desugared the program twice, and the options filled in once were too many arguments the second time. Where pandas has a choice, the spec's is taken, and the script says so: groups in the order first seen (sort=False), a trailing window over the rows there are (min_periods=1), rank sharing a rank between equal cells (method='min'), the population deviation (ddof=0), a right frame's duplicate column named _right, and a right or outer join compared sorted, since pandas orders those rows by the right frame or by key where Crow keeps the left frame's order and appends the unmatched. Not compared: stats, a display, and fill of a moment column, which neither side needed.

Design Note: a window is a frame's, an indicator a series's. Considered: leaving trailing aggregates to the market package's indicators (sma[bars.c, 3] is a trailing mean over one series), so that a frame has no second way to a moving average. Decided: window computes within a frame's partitions, in its order — one column holding a series per symbol, each windowed on its own — where an indicator takes one series; over one series, sma[df.close, 3] and window[df, 'close', 'mean', n = 3] agree. A trailing window's first rows are the rows there are, as SQL's window frames give them (pandas leaves them empty until the window fills).

A frame's type is its columns. A frame built in the program (frame.new[], a column written under a name the program writes), a query a database described (see db, Typed cells), and a frame derived from either through select, a mask (df[mask]), sort, head, tail, fill, stack, join, rename, group or pivot carries its columns in its type, each with its cells' type (a column written from another keeps its cells' type; a pivot's rows column, and its others as they show). A column written under a name the program computes (df.name = xs) leaves the columns the type knows and makes the frame open: a column it cannot name may be there. A column written binds the frame anew: after df.x = xs, df has x from that line on, and before it the frame it was. Where branches, or a loop's rounds, meet, a frame has the columns they all give it; a column only some add may be there, and is read as the program runs. A function handed frames of different columns is a copy per set of columns, so it reads the columns each call hands it. Where a frame's columns are all known, a column it lacks — read as df.x, named where select, sort, fill, rename, group or join takes a column, or named by a table (key, mark, delta, hide) or a chart (candles, lines, bars_y) — is refused before the program runs, in both modes, with the columns the frame has (frame has no property or column 'cost' — its columns are 'price', and, read in a function, the parameter the frame was handed as); the stop above is for a frame whose columns show only as it runs (a file load reads then, a query no database described, a column a variable names).

A frame loaded from a file has the columns the program reads. frame.load cannot see a file's columns before the program runs, and neither can the program state them: the reads of the frame's cells say what they are. A cell walked and handed to upper, or to a function that reads it as text, is text; one met as a number — compared with one, added to one, halved — is a number, held as floats whichever the file wrote, so q gt 20 holds for a file's 20.5 and q / 2 of its 7 is 3.5, as a variable that may hold a float divides (§1); one handed to what takes nothing but an int — a position, xs[q], or head, repeat, slice — is an int; one decided on is a bool; one met beside a moment is a moment. A function the cell is handed to says what its own body reads the parameter as. The frame is held to that shape where it is bound, before any cell is read: a column missing, or holding another kind — numbers where the program reads text, text where it reads numbers, floats where a position reads ints — stops the program there with the column, what it holds, what the program reads and the read that asked (column 'slot' holds floats where the program reads ints (a position in labels at line 12)), the same words in both modes. A column of whole numbers the program reads as numbers is widened to floats at the load, exactly: a whole number beyond 2^53 stops the load there rather than lose digits (read it with int[…] where it is compared). From then on the frame's cells are typed, in both modes, and nothing is read first — each a cell that can be missing, since a file's cell can be empty and a record's field null: read one at a time, a missing one is an error value of reason missing (below; the reads had typed the cells plain, and a missing one had been read as '' or NaN with .ok true, in both modes). A column the program writes on the frame (df.when = …) is the program's from then on: what it reads of it after the write — on the frame, on one a verb derives from it, in a function it is handed to — says nothing of the file, which need not have it (a column of moments written and compared had been asked of the file, and the load had stopped: the frame has no column 'when'). A column no read says anything of stays as it comes, a parsed value read as its use implies where it is used (see JSON). A column read as two kinds — text here, a number there — is refused before the program runs, naming both reads. A page's data source (fetch[url], poll[url, seconds], ui) is such a frame too: its reads say its columns, the fact carries them to the session, and the answer is held to them where it arrives — its records a frame, a column of whole numbers read as numbers floats, an answer of no records the table with no rows yet — before the page shows; what is not what the page reads (no answer, no JSON, a column missing or of another kind) stops the session there, told to the reader as a handler's stop is, the reason in the server's log with the column, what it holds, what the program reads and the read that asked — the same in both modes.

Rejected: each is a second way of saying what a value already says, and the sample asks the programmer to invent one. Considered: reading every cell first, as a parsed value's (the way until 2026-10-08). Rejected: the program did nothing wrong, and the compiled program had not held a function handed such a cell. Decided: the reads say the columns, the file is held to them where it is loaded, and a column no read types stays as it comes. Considered, and built for a day: a cell compared with an int held as ints, so a file's 20.5 stopped the load where the program wrote q gt 20. Rejected (Vijay, 2026-10-08: "q gt 20 when q = 20.5 should work. as a human being, it is obvious ... you are comparing two numbers. whether it is a float or int, it does not matter"): the program says a number, which kind the file's are is the file's business, and a program's meaning must not turn on whether the file wrote 7 or 7.0 — the language's own rule, that a variable which may hold a float is a float, says what the column is. A page's data source is held the same way where its answer arrives, in the session both modes share (2026-10-08: the interpreter had answered an empty map and registered no source at all, and the compiled program had turned the records into a frame of its own at every render).

Design Note: a frame's reassignment is a new binding. Considered: one type per variable, as every other variable has, the frame's columns joined over its assignments — which loses exactly the columns a program adds (df.x = xs, then df.x); and a name per shape (df2 = … for every column added), which asks the program to rename what it changes, and makes a loop that adds columns impossible to write. Decided (Vijay, 2026-09-29): a frame variable's type is its last assignment's — a new binding where its columns change, as a Rust let shadows one — and where ways through meet it has the columns they share.

Design Note: a frame operation's misuse stops the program. Considered: error values of kind 'frame', which the table of kinds listed for filter, sort, group and join, and which the interpreter answered. Rejected: the operations are typed as giving a frame, which cannot fail, and the compiled program stopped — so a program that checked .ok worked in one mode only — and the same column the frame lacks, read as df.col, stops the program. A misuse is the program's mistake, not something it reads: an error value would carry it to wherever a decision first met it. Boolean Masks

Filtering uses ordinary Crow expressions that evaluate to boolean arrays. These operations are vectorized (element-wise):

  • eq ne gt lt gte lte — column vs scalar → boolean array (the scalar may come first: 50 lt df.age)
  • 'late' in df.note, starts[df.symbol, 'A'], ends[df.note, 'k'] — a text column tested cell by cell → boolean array, a missing cell false
  • and / or — two boolean arrays → boolean array; a bool and a boolean array → each item joined with the bool
  • not — boolean array → boolean array

A column compared with a list, a column or a tensor is one truth, as two lists compare (see Comparison), and so are two masks compared whole: df.id eq ['a', 'b'] says whether the column holds those cells, df.id eq 'a' which rows hold it.

A tensor compared with a number is a mask of the tensor's shape, as numpy's is: a vector's is a list of bools, a matrix's its rows of bools — [[1.0, 2.0], [3.0, 4.0]] gt 2.0 is [[false, false], [true, true]] — and deeper for more axes. It keeps that shape through not, and and or (two masks of one shape join truth by truth; of two shapes the program stops), where numbers are taken it is a tensor of that shape — true 1, false 0 — so where[m gt 0.0, m, 0.0 * m] is a matrix and sum[m gt 2.0] counts, and a matrix indexed by a mask of its shape is its numbers where the mask is true, in row order (see Indexing). A tensor whose rank the program does not show — a field given a vector in one place and a matrix in another — compared with a number is refused, naming it: its mask's shape would be decided by nothing (reshape or flatten it first). (Until 2026-10-18 a matrix's mask had been one flat list of its numbers' answers: where over it answered a vector, and no index of the matrix took it.)

use frame

Each cell is compared with the value as two values compare (see Comparison): numbers by value, exactly — NaN holds only ne — text by its characters and ordered by character code, bools equal or not, moments by instant. A value of another kind than the cells — df.name eq 2 of a column of text — and an order between kinds with none — gt on a column of bools — are refused where the column's type is known, and stop the program where it shows only as it runs (a file load reads). Missing values compare as false for every operator, ne included — they are excluded by any mask, and not (df.age gt 50) is what keeps them. A list compared with one value is a mask the same way. (Compiled, a missing or NaN cell had been false for ne, eq had been nearness within 2⁻⁵², a column of text had been parsed as numbers and a column of bools had compared as nothing; the interpreter had counted a missing cell as ne and stopped on an order of text; a list of values that can fail, compared with one value, had not built.)

A frame's mask is computed in one pass. df[df.age gt 50 and df.name ne 'bob'] — a mask that compares the frame's own columns with values that only read, asks a column's .ok, and combines those with and, or and not — reads no column into a list and makes no mask per comparison: the rows are decided block by block, across the cores for a large frame, each cell as its comparison decides it. The rows kept are the mask's, and a column the frame lacks or an order between kinds with none stops with the operator's words at the first comparison that meets it. The same in both modes.

A column's .ok is its rows' validity — true where the cell is present, false where it is missing — so df[df.age.ok] keeps the complete rows. (Every other value's .ok is its own status: a list that did not fail is ok.) A frame shows a missing cell as missing, and a column shown as a list shows it as the error it is read as, error: missing; a NaN a number column holds is a value, and shows as nan (until 2026-10-08 a missing cell had shown as nan too, in a text column as well). Read one at a time (df.age[3]), a cell of a column that can have missing cells is fallible: a missing one is an error value of reason missing, which computes and cannot be decided on (§10), so .ok guards it and a guard narrows it to its value. The columns that can are a loaded file's and a page's data source's, whose columns the program's reads type (A frame loaded from a file, above: an empty cell, a null or absent field), a database column that can hold NULL (see db, Typed cells) and the side of a join a row can have no match on — a left join's right columns, a right join's left ones, all of an outer join's. fill[df, 'age', 0] gives a column a value where it had none, and its cells are plain again, as are a column's that cannot have missing cells. A mask decides every row, so a list of values that can fail — built from such cells — is refused as one, in both modes: fill the column first, or guard each value with .ok. Handed whole to a function that takes numbers — mean[df.age], median, sma[bars.c, 3] — or used in arithmetic — df.price * 2, df.a + df.b — a column is its numbers, as a list of numbers is, and the answer is a tensor; a missing cell stops the program (row 3 of the column is missing — fill the column first: fill[frame, 'column', value]), and so does a column of text or of bools, in both modes. (Compiled, a missing cell had been read as 0 and a column of text parsed, where the interpreter stopped — or, for df.a + df.b, refused the sum.) A comparison is a mask, as above. A column written from another (df.b = df.a) keeps its kind and its missing cells, even when every cell is missing.

Design Note: a missing cell is an error, not a placeholder. Considered: reading a missing cell as its column's placeholder in both modes — NaN in a number column, 0 in an int one, false in a bool one, nan in text — as a filter reads it, which both modes did. Honest for a number, since NaN compares as false; for an int or a bool it is a guess the program cannot tell from a value, of the kind §10 refuses elsewhere (an unmatched row's count read as 0). Decided (Vijay, 2026-09-25, typed frames decision 3): where the schema says a column can have missing cells its cells are fallible, and where it says it cannot they are plain, so no cell is a guess.

Dynamic column names need no special syntax — a string variable works everywhere a column name does:

col = 'age'
sorted = sort[df, col]

Design Note: No Bare-Name Column References

What was considered (and originally shipped): Bare identifiers as column names — sort[df, age], group[df, dept, [salary, mean]] — where an identifier that isn't a defined variable is treated as a column-name string.

Why it was removed:

  1. Scope-dependent meaning. Adding a local variable named age silently changed sort[df, age] from a column reference into a value argument. Code broke at a distance with no error.
  2. Interpreter–transpiler divergence. The interpreter preferred the variable when one existed; the transpiler force-converted certain argument positions to strings regardless. The same program meant different things in the two modes, violating the parity rule.
  3. Violates rule 19 (no DSL). A second evaluation rule inside frame calls means a line of Crow can't be read without knowing which builtin it appears in.

What to use instead: Strings for column names, expressions for computation — as specified above. One mechanism, no sugar, dynamic columns free.
